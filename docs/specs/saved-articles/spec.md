# 변환한 글 저장과 저장한 글 목록

로그인한 사용자가 변환 결과를 내 계정에 저장하고, 저장한 글 목록에서 저장 당시 내용 그대로 다시 열어 보거나 지운다.

## 연결된 소스

- [prototype.html](prototype.html): 승인된 화면. 변환기에 붙는 저장 버튼과 그 상태, 헤더의 "저장한 글"과 로그인 항목, 바뀐 하단 문구, 저장한 글 목록(빈 상태 포함), 저장한 글 보기, 삭제 확인 대화상자의 배치와 문구를 이 파일이 정한다. 동작은 이 스펙의 수용 기준이 정하고, 배치와 문구는 프로토타입을 따른다. 프로토타입 속 로그인은 바로 로그인된 상태로 돌아오는 흉내일 뿐이고, 실제 로그인 화면은 아래 Setup에서 붙는 Supabase 공식 블록이다.
- [docs/specs/url-to-markdown/spec.md](../url-to-markdown/spec.md): 이미 출시한 변환 화면의 동작. 이 스펙은 그 화면의 내보내기 첫 줄에 저장 버튼을 더하고, 하단 문구를 바꾸고, 헤더에 항목을 더한다. 그 밖의 변환·내보내기 동작은 그 스펙 그대로다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md): 일반 UI는 shadcn/ui 컴포넌트와 semantic token으로 구성한다.
- [docs/decisions/dependency-versions.md](../../decisions/dependency-versions.md): 새로 들이는 의존성의 버전 범위 규칙.
- [GLOSSARY.md](../../../GLOSSARY.md): "저장한 글"의 정의.

## 사용자가 얻는 것

- 변환한 글을 버튼 하나로 내 계정에 저장한다.
- 원문이 바뀌거나 사라져도, 저장한 때의 제목·메타·본문 그대로 다시 본다.
- 다른 기기나 브라우저에서 로그인해도 같은 목록이 보인다.
- 저장한 글에서도 복사, `.md` 다운로드, 프롬프트를 붙여 ChatGPT·Claude로 넘기기를 그대로 쓴다.
- 필요 없어진 글은 목록이나 보기 화면에서 지운다.

## 범위

1. **저장**: 변환기의 결과 카드, 복사하기·`.md` 다운로드와 같은 줄에 저장 버튼.
2. **저장한 글 목록**: 헤더의 "저장한 글"로 들어가는 화면.
3. **저장한 글 보기**: 목록에서 한 글을 연 화면.
4. **삭제**: 목록과 보기 화면에서, 확인을 거쳐 지운다.
5. **헤더와 하단 문구**: 로그인 상태에 따른 헤더 항목, 저장 정책을 알리는 하단 문구.

## 수용 기준

### 저장
- 로그인한 상태에서 결과 카드의 **저장**을 누르면, 그 변환의 제목·저자·게시일·사이트·URL·Markdown 본문과 저장 시각이 내 계정에 저장된다.
- 저장하는 동안 버튼은 비활성화되고 "저장 중…"으로 바뀐다. 끝나면 "저장됨"으로 바뀌고 "저장했습니다" 토스트가 뜬다. 토스트의 "저장한 글 보기"를 누르면 목록으로 간다.
- 이미 저장한 URL의 결과를 보면, 버튼은 처음부터 "저장됨"으로 보인다.
- "저장됨"을 다시 누르면 같은 URL의 저장한 글이 지금 화면의 변환 내용과 저장 시각으로 바뀐다. 목록에 새 항목이 생기지 않고, "저장한 글을 지금 변환한 내용으로 바꿨습니다" 토스트가 뜬다.
- 같은 URL은 계정마다 목록에 하나만 있다.
- 프롬프트 선택과 직접 입력한 프롬프트는 저장하지 않는다.

### 로그아웃 상태
- 로그아웃 상태에서는 헤더에 "로그인"만 보이고 "저장한 글"과 계정 버튼은 보이지 않는다.
- 결과 카드의 저장 버튼은 "로그인하고 저장"으로 보인다. 누르면 로그인 화면으로 간다.
- 로그인을 마치면 변환기로 돌아와 같은 URL의 결과가 다시 보이고, 그 글이 자동으로 저장돼 버튼이 "저장됨"이다. 이미 저장한 URL이었다면 새로 저장하지 않고 "저장됨"만 보인다.
- 로그아웃 상태로 저장한 글 목록이나 보기 화면 주소를 열면 로그인 화면으로 간다.

### 저장한 글 목록
- 최근에 저장(또는 다시 저장)한 글이 위에 온다. 제목 위에 "N개 · 최근에 저장한 순서"가 보인다.
- 각 줄에는 제목, 사이트, 저장한 날짜, 삭제 버튼이 있다. 제목이 길면 두 줄까지 보이고 나머지는 말줄임으로 줄인다.
- 줄을 누르면 그 글의 보기 화면이 열린다.
- 저장한 글이 없으면 "아직 저장한 글이 없습니다" 빈 화면과 "글 변환하러 가기" 버튼이 보인다.
- 다른 계정이 저장한 글은 보이지 않는다.

### 저장한 글 보기
- 변환 결과와 같은 카드로 보여 준다. 제목, 메타 줄(저자 · 게시일 · 사이트 · 글자 수, 빈 항목은 빠짐), 내보내기 패널, 렌더링된 본문이 있다.
- 메타 줄 아래에 "{저장 시각}에 저장한 내용입니다"가 보인다.
- 원문을 다시 가져오지 않는다. 본문과 메타는 저장된 내용 그대로다.
- 복사, `.md` 다운로드, 프롬프트 선택, ChatGPT·Claude로 열기(4,000자 기준 포함)는 변환기와 똑같이 동작하고, 저장된 Markdown을 쓴다. 저장 버튼은 없다.
- 위쪽에 "← 저장한 글"(목록으로), "원문 열기"(원래 URL을 새 탭으로), "삭제"가 있다.
- 다른 계정의 저장한 글 주소를 열면 그 글은 보이지 않는다.

### 삭제
- 목록의 삭제 버튼이나 보기 화면의 **삭제**를 누르면 "이 글을 삭제할까요?" 확인 대화상자가 뜬다. 대화상자에는 글 제목과 되돌릴 수 없다는 안내가 있다.
- **취소**, 바깥 클릭, Esc로 닫으면 아무것도 지워지지 않는다.
- **삭제**를 누르면 그 글이 내 계정에서 지워지고 "삭제했습니다" 토스트가 뜬다. 목록에서는 그 줄이 사라지고, 보기 화면에서는 목록으로 돌아간다.
- 마지막 글을 지우면 목록이 빈 화면으로 바뀐다.
- 지운 URL을 변환기에서 다시 변환하면 버튼은 "저장"으로 보인다.

### 헤더와 하단 문구
- 로그인한 상태의 헤더에는 "저장한 글", 계정 버튼, 다크 모드 버튼이 있다. 계정 버튼은 `/settings`로 간다.
- 변환기 하단 문구는 "저장 버튼을 누른 글만 내 계정에 저장합니다. 프롬프트는 저장하지 않습니다."다.

### 반응형과 다크 모드
- 휴대폰 너비(약 390px)에서 저장 버튼은 숨겨지지 않고 복사·다운로드 옆이나 다음 줄로 줄바꿈된다. 목록 줄과 삭제 대화상자도 가로로 넘치지 않는다.
- 새 화면은 기존 `.dark` 토큰으로 칠한다. 색을 화면에서 따로 지정하지 않는다.

## 정해진 제약과 근거

- **저장한 글은 로그인한 계정에 남긴다.** 사용자가 브라우저 저장 방식과 비교한 뒤 골랐다. 기기를 바꿔도 같은 목록을 보기 위해서다.
- **저장은 저장 시점의 변환 결과 사본이다.** 사용자가 URL만 남기는 북마크 방식과 비교한 뒤 골랐다. 원문이 바뀌거나 사라지거나 막혀도 다시 볼 수 있고, 열 때 기다리지 않는다.
- **같은 URL은 계정마다 하나이고, 다시 저장하면 바꾼다.** 사용자가 저장할 때마다 새로 쌓는 방식과 비교한 뒤 골랐다. 목록에 같은 제목이 반복되지 않는다.
- **삭제는 확인을 거친다.** 사용자가 정했다. 지운 사본은 되돌릴 수 없고, 원문이 사라졌다면 다시 만들 수도 없다.
- **"로그인하고 저장"으로 로그인하면 돌아와서 자동으로 저장한다.** 사용자가 한 번 더 누르게 하는 방식과 비교한 뒤 골랐다. 저장하려던 의도를 그대로 잇는다.
- **프롬프트는 저장하지 않는다.** url-to-markdown 스펙에서 직접 입력 프롬프트를 1회용으로 정한 결정을 유지한다.
- **저장소와 로그인은 Supabase다.** 이메일·비밀번호 로그인(이메일 확인 끔)과 함께 붙이는 Supabase 프로젝트를 쓴다. 저장한 글은 소유자만 읽고, 쓰고, 지울 수 있어야 한다.
  - 에이전트 맥락 점검 결과: 공식 스킬 `supabase`, `supabase-postgres-best-practices`는 이미 설치돼 있다(`skills-lock.json`). 공식 문서 색인 `https://supabase.com/llms.txt`는 작업 시작 때 가져오도록 AGENTS.md에 안내를 넣었다. 공식 MCP 서버는 쓰지 않는다. CLI로 충분하다.
- **UI는 ui-composition 결정을 따른다.** 삭제 확인은 shadcn/ui AlertDialog, 토스트는 기존 Sonner, 빈 목록은 Empty, 버튼은 Button을 쓴다.

## 가정 (바꿔도 되는 기본값)

- 같은 URL인지는 변환에 쓴 URL 문자열(앞뒤 공백 제거)이 같은지로 판단한다. 쿼리나 끝 `/`만 다른 주소는 다른 글로 본다.
- 목록은 한 화면에 전부 보여 준다. 페이지 나누기나 더 보기는 두지 않는다.
- 목록의 저장 날짜는 "2026년 11월 18일 저장", 보기 화면의 저장 시각은 "2026년 11월 18일 오후 4:20"처럼 한국어 형식으로 보여 준다.
- 저장한 글 보기에서 없는 글(지웠거나 다른 계정의 글)을 열면 "찾을 수 없는 글입니다"와 목록으로 돌아가는 버튼을 보여 준다.
- 로그아웃 상태로 목록·보기 주소를 열어 로그인하면, 원래 열려던 화면으로 돌아간다.
- "로그인하고 저장"에서 돌아왔을 때 보이는 결과는 같은 URL을 다시 변환한 것이다. 로그인 전 화면에 있던 변환과 내용이 조금 다를 수 있다.
- 헤더의 계정 버튼은 사용자 표시 이름의 첫 글자를 보여 준다. 표시 이름이 없으면 이메일 첫 글자를 쓴다.

## 범위 밖

- **검색, 태그, 폴더, 정렬 바꾸기**: 요청 범위가 저장·목록·보기·삭제다.
- **저장한 글 공유나 공개 링크**: 저장한 글은 소유자만 본다.
- **원문 변경 감지, 자동 갱신, 저장한 글 편집**: 저장은 저장 시점 사본이다. 바꾸려면 다시 변환해 저장한다.
- **저장한 글 보기에서 다시 변환하기**: 변환기에서 같은 URL을 다시 변환해 저장하면 된다.
- **프롬프트·변환 기록 저장, 저장 개수 제한, 여러 글 한꺼번에 지우기나 내보내기.**
- **로그인 화면 자체, 비밀번호 재설정, 계정 삭제**: Supabase 설정 작업의 범위다.
- **보안 하드닝**: AGENTS.md의 검증 예산이 스펙에 없는 하드닝을 범위 밖으로 정했다. 소유자만 접근하는 규칙은 하드닝이 아니라 이 스펙의 수용 기준이다.

## 남은 위험

- **목록이 길어지면 느려질 수 있다.** 페이지 나누기 없이 전부 불러오고, 각 글이 긴 Markdown(위키백과 문서는 3만 자 넘음)을 품는다. 목록에는 본문 없이 제목·사이트·날짜만 불러와야 이 위험이 줄어든다.
- **같은 글이 다른 URL로 두 번 저장될 수 있다.** URL 문자열이 조금만 달라도 다른 글로 보기 때문이다.
- **로그인 설정이 아직 끝나지 않았다.** Setup 항목이 끝나기 전에는 이 스펙의 어느 기준도 확인할 수 없다.
- **url-to-markdown 스펙과 어긋난다.** 그 스펙은 "로그인, 변환 기록"을 범위 밖으로, 하단 문구를 "입력한 URL과 프롬프트는 저장하지 않습니다."로 적었다. 이 스펙이 출시되면 그 두 곳은 이 스펙이 대신한다.

## Setup before implementation

- Supabase 이메일·비밀번호 로그인(이메일 확인 끔) 설정 완료 — 저장·목록·보기 전체가 로그인한 사용자를 전제한다 — 완료 조건: 시험 계정으로 앱에서 가입·로그인한 뒤 `/settings`가 열리고, 로그아웃하면 `/settings`가 로그인 화면으로 보낸다.
- Supabase CLI가 로그인돼 있고 이 저장소가 대상 Cloud 프로젝트에 연결됨 — 저장한 글 테이블과 접근 규칙을 hosted 프로젝트에 마이그레이션으로 반영하기 위해서다 — 완료 조건: `supabase projects list`가 계정의 프로젝트를 보여 주고, `supabase migration list`가 원격 이력을 보여 준다.
